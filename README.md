# Lazy Ledger

本文件记录这个 skill 后续要补的能力，方便我们后面按同一套方向继续迭代。

## 目标

把现在的本地 JSON 记账工具，逐步做成一个更顺手的个人记账系统：

- 记账时更懂用户习惯
- 数据管理更稳定
- 本地查看和修改更方便
- 能覆盖报表、预算、账户等完整场景

## 规划中的功能

### 1. 记账和分类习惯

目标：让后续记账越来越贴近用户自己的习惯，而不是每次都从通用规则重新猜。

计划补充：

- 用户级分类偏好：同一个商户默认归到用户常用分类
- 商户别名和关键词映射：例如同一个店名、缩写、付款对象映射到统一商户
- 常见交易对手习惯：红包、转账、代付、报销等按历史习惯识别
- 用户纠错学习：当用户把某笔从 `其他` 改成指定分类后，后续优先沿用
- 分类规则优先级：用户自定义规则高于内置默认规则

建议落地方式：

- 在本地存一份 `preferences` / `merchant_rules` / `category_rules`
- 每次记账先查用户规则，再回退到内置规则
- 保留“为什么这样分类”的可解释信息，方便复核

### 2. 本地 Web 页面和数据库

目标：不要只靠静态 HTML，看账、改账、筛选和导入都能在本地页面里完成。

计划补充：

- 本地启动一个小型 Web 程序，而不是只生成静态页
- 用本地数据库保存数据，优先考虑 `SQLite`
- 支持新增、编辑、删除、搜索、筛选、分页
- 支持本地报表、最近流水、导入记录、体检结果查看
- 页面只在本机运行，不依赖外网服务

建议落地方式：

- 后端：一个很小的本地服务，例如 `Flask` / `FastAPI`
- 数据层：`SQLite`，替代当前直接写 JSON 作为主存储
- 前端：轻量本地页面，支持表格、筛选和基础图表
- 保留 JSON 导出能力，避免数据被锁死

### 3. 多账户概念

目标：区分现金、微信零钱、银行卡、信用卡等账户，不把所有流水混成一个池子。

计划补充：

- 账户表：账户名、类型、币种、是否默认
- 每笔流水关联账户
- 转账支持“从哪个账户到哪个账户”
- 报表支持按账户筛选
- 支持账户余额快照或推算余额

建议优先支持的账户类型：

- 现金
- 微信零钱
- 支付宝余额
- 银行卡
- 信用卡

### 4. 多个命令和完整工作流

目标：把“记账、查账、预算、报表、账户管理”拆成更完整的一组命令，而不是只靠少数几个入口。

建议补充的命令：

- `add`：单笔记账
- `parse`：只解析不写入
- `import-tsv`：批量导入整理好的流水
- `recent`：最近流水
- `search`：按商户、分类、时间、金额查找
- `summary`：汇总统计
- `budget`：预算设置和预算查看
- `account`：账户新增、编辑、列表
- `report`：本地报表生成或打开
- `doctor`：账本体检

## 建议实施顺序

1. 先补“用户习惯规则”和“多账户模型”
2. 再把存储从单一 JSON 升级到 `SQLite`
3. 然后做本地 Web 程序，接上真实数据库
4. 最后扩充预算、账户管理、交互式报表

## 备注

当前静态 HTML 报表可以继续保留，作为轻量导出或只读查看模式。后续本地 Web 程序上线后，静态页可以退成“导出结果”，而不是主入口。
